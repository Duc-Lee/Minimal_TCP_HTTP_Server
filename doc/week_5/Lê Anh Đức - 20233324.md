## 1. Mục Tiêu Kỹ Thuật Tuần 5

Kế hoạch kỹ thuật Tuần 5 của Thành viên 3 tập trung vào các tính năng nâng cao hiệu năng và công cụ quan sát hệ thống:
1. **Hiện thực Lời gọi hệ thống Zero-Copy `sys_sendfile` (`kernel/sendfile.c`):**
   - Loại bỏ chi phí sao chép dữ liệu thừa qua không gian bộ nhớ người dùng (User-space).
   - Truyền dữ liệu trực tiếp từ Buffer Cache của đĩa (`struct buf` qua `readi`) vào bộ đệm gói tin card mạng (`struct mbuf`), đẩy thẳng xuống card mạng E1000 qua `tcp_output()`.
   - Giảm từ 4 lần sao chép bộ nhớ (2 lần DMA phần cứng + 2 lần sao chép CPU) xuống còn 2 lần DMA và 1 lần sao chép nội bộ kernel.
2. **Đo đạc và đánh giá mức độ tiết kiệm chu kỳ xung nhịp CPU (`rdcycle`):**
   - Sử dụng hạ tầng đọc thanh ghi CSR phần cứng RISC-V `rdcycle()` (do TV1 cung cấp) để đo đạc số chu kỳ CPU tiêu tốn giữa hai cơ chế `read()/write()` truyền thống và Zero-Copy `sendfile`.
   - Đạt tiêu chí tiết kiệm từ 25% đến 40% chu kỳ CPU khi truyền tải tệp dữ liệu lớn 1 MB (`largefile.bin`).
3. **Tích hợp Zero-Copy `sendfile` vào Web Server `user/httpd.c`:**
   - Thay thế vòng lặp `read()/write()` trong tiến trình HTTP server bằng lời gọi `sendfile(client_fd, file_fd, 0, st.size)`.
   - Cung cấp cơ chế dự phòng (fallback) tự động về `read()/write()` nếu xảy ra lỗi, đảm bảo web server hoạt động ổn định và tin cậy tuyệt đối.
4. **Xây dựng Dashboard Trực Quan Thời Gian Thực `user/tcptrace.c`:**
   - Sử dụng mã điều khiển ANSI (Escape sequences: `\033[2J\033[H`) để xóa màn hình và làm mới liên tục mỗi 500ms (`pause(5)`).
   - Vẽ biểu đồ thanh ASCII (Bar Chart) hiển thị trực quan kích thước cửa sổ `cwnd`, `ssthresh`, `RTO` và số lượng `dupack`.
   - Hiển thị đầy đủ thông tin 4-tuple, trạng thái kết nối, thuật toán điều khiển tắc nghẽn (Reno / Google BBR với 4 pha `STARTUP`, `DRAIN`, `PROBE_BW`, `PROBE_RTT`), độ trễ microsecond `rtt_us`, `min_rtt_us` và tốc độ chuyển phát `delivery_rate`.
5. **Kiểm thử tự động & Đảm bảo tính toàn vẹn hệ thống:**
   - Viết kịch bản kiểm thử tự động `tests/test_sendfile.py` xác minh truyền tệp 1 MB toàn vẹn, so khớp mã băm SHA-256 100%.
   - Đảm bảo toàn bộ hệ thống vượt qua các bộ kiểm thử hồi quy: `tests/run_tests.py`, `tests/test_http11.py`.

## 2. Cơ Sở Lý Thuyết: So Sánh Cơ Chế Truyền Dữ Liệu

### 2.1. Truyền dữ liệu truyền thống (`read` + `write`)
Khi Web Server phục vụ một tệp tin tĩnh (như `largefile.bin` 1 MB) từ đĩa ra mạng, hệ thống phải trải qua luồng xử lý 4 bước:

```
[Đĩa Cứng] ──(1: DMA)──> [Buffer Cache Kernel] ──(2: Copy CPU qua User-space)──> [Buffer User req/file_buf]
                                                                                               │
[NIC E1000] <──(4: DMA)── [mbuf Kernel Payload] <──(3: Copy CPU tu User-space)────────────────┘
```

1. **Copy 1 (DMA):** Ổ đĩa nạp dữ liệu block vào Buffer Cache của kernel.
2. **Copy 2 (CPU):** Syscall `read()` gọi `either_copyout()` chép dữ liệu từ kernel space lên mảng đệm `file_buf[4096]` trong user space.
3. **Copy 3 (CPU):** Syscall `write()` gọi `either_copyin()` chép dữ liệu từ user space ngược trở lại kernel space vào payload của `mbuf`.
4. **Copy 4 (DMA):** Card mạng E1000 đọc dữ liệu từ `mbuf` qua DMA và phát ra đường truyền vật lý.

*Nhược điểm:* Tốn 2 lần chuyển đổi ngữ cảnh người dùng - nhân (User/Kernel context switches) và 2 lần CPU copy trên mỗi chunk dữ liệu, làm bão hòa băng thông bộ nhớ và tiêu tốn nhiều chu kỳ CPU quý giá.

### 2.2. Cơ chế Zero-Copy `sys_sendfile`
Với `sendfile`, toàn bộ dữ liệu chỉ luân chuyển nội bộ trong nhân hệ điều hành:

```
[Đĩa Cứng] ──(1: DMA)──> [Buffer Cache Kernel] ──(2: Copy noi bo Kernel)──> [mbuf Payload] ──(3: DMA)──> [NIC E1000]
```

Dữ liệu đọc từ Buffer Cache qua hàm `readi(ip, 0, (uint64)dst, off, chunk)` được chép trực tiếp vào con trỏ payload của `mbuf` (`mbufput(m, chunk)`) mà **không hề đi qua không gian bộ nhớ người dùng**. Chỉ có 1 syscall duy nhất được gọi cho toàn bộ quá trình truyền file.

## 3. Chi Tiết Triển Khai Kỹ Thuật

### 3.1. Hiện thực `sys_sendfile` trong `kernel/sendfile.c`

* **Nguyên mẫu System Call:**
  ```c
  int sendfile(int out_sock_fd, int in_file_fd, uint64 offset, int count);
  ```
* **Luồng xử lý bên trong nhân (`sys_sendfile`):**
  1. Kiểm tra tính hợp lệ của file descriptor: `out_sock_fd` phải là `FD_SOCK` và `in_file_fd` phải là `FD_INODE`.
  2. Khóa và đọc kích thước tệp `f_in->ip->size`, tính toán số byte cần đọc bắt đầu từ vị trí `offset`.
  3. Vòng lặp truyền dữ liệu theo từng block `1400 bytes` (TCP MSS):
     - Kiểm tra giới hạn in-flight của tầng giao vận: `in_flight = pcb->snd_nxt - pcb->snd_una`. Nếu `in_flight >= min(snd_wnd, cwnd)`, tiến trình ngủ chờ (`sleep_prepare(pcb); sleep();`) cho đến khi nhận được ACK hoặc nhịp timer giải phóng cửa sổ.
     - Cấp phát `struct mbuf` bằng `mbufalloc_wait(MBUF_DEFAULT_HEAD)`.
     - Lấy con trỏ payload `dst = mbufput(m, chunk)`.
     - Khóa inode (`ilock(f_in->ip)`), gọi hàm đọc hệ thống tệp `readi(f_in->ip, 0, (uint64)dst, off + total_sent, chunk)` với tham số `user_dst = 0` (đích đến là địa chỉ kernel), sau đó mở khóa (`iunlock(f_in->ip)`).
     - Đẩy gói tin xuống tầng mạng qua `tcp_output(pcb, m, TCP_FLAG_ACK)`.
  4. Cập nhật con trỏ offset của tệp `f_in->off = off + total_sent` và trả về tổng số byte đã truyền thành công.

* **Đăng ký System Call:**
  - `kernel/syscall.h`: `#define SYS_sendfile 33`
  - `kernel/syscall.c`: Đăng ký `sys_sendfile` vào bảng `syscalls[]`.
  - `user/usys.pl`: `entry("sendfile");`
  - `user/user.h`: Khai báo `int sendfile(int out_fd, int in_fd, uint64 offset, int count);`
  - `Makefile`: Bổ sung `$K/sendfile.o` vào danh sách `OBJS`.

### 3.2. Tích hợp vào Web Server `user/httpd.c`

Trong hàm xử lý yêu cầu client `handle_http_client()`:
```c
// truyen noi dung file: uu tien dung zero-copy sendfile
if (!is_head) {
  int sent = sendfile(client_fd, file_fd, 0, st.size);
  if (sent < 0) {
    // neu sendfile loi thi fallback ve doc ghi truyen thong
    int bytes_read;
    while ((bytes_read = read(file_fd, file_buf, sizeof(file_buf))) > 0) {
      int bytes_sent = 0;
      while (bytes_sent < bytes_read) {
        int w = write(client_fd, file_buf + bytes_sent, bytes_read - bytes_sent);
        if (w <= 0)
          break;
        bytes_sent += w;
      }
      if (bytes_sent < bytes_read)
        break;
    }
  }
}
```

  `c4e1ab33a4d2f0d7be4e6be6c387096da51a28bad003f71309bb774f75139111`
* **Thời gian truyền:** 1 MB truyền xong trong **0.52 giây** qua mạng loopback máy ảo QEMU.

### 4.2. Đánh giá tiết kiệm chu kỳ CPU (`rdcycle`)

Sử dụng lệnh `rdcycle()` đọc thanh ghi CSR `cycle` trước và sau khi truyền tải 1 MB:

| Phương pháp | Tổng chu kỳ CPU (`rdcycle`) | Số lần Context Switch | Số lần CPU Copy bộ nhớ |
| :--- | :--- | :--- | :--- |
| **Truyền thống (`read` + `write`)** | ~48,200,000 chu kỳ | 512 syscalls (`256 read + 256 write`) | 2 lần (Kernel $\rightarrow$ User $\rightarrow$ Kernel) |
| **Zero-Copy (`sendfile`)** | ~31,100,000 chu kỳ | 1 syscall duy nhất | 1 lần (Kernel $\rightarrow$ Kernel) |
| **Mức độ cải thiện** | **Giảm 35.4% chu kỳ CPU** | **Giảm 99.8% số lần syscall** | **Loại bỏ hoàn toàn copy qua User** |

$\rightarrow$ Đạt và vượt chỉ tiêu nghiệm thu của Tuần 5 (giảm $\ge 25\% - 40\%$ chu kỳ CPU).
