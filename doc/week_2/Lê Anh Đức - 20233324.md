## 2. Công việc đã thực hiện

### a. Xử lý đóng socket và chống mất đuôi file (`kernel/sock.c`)
- **Lỗi mất đuôi file trong `sock_close()`:**
  - *Nguyên nhân:* Khi `httpd` gửi xong file thì gọi `close()` ngay. Trước đây hàm `sock_close()` lập tức đổi trạng thái sang `TCP_FIN_WAIT_1` và gửi cờ FIN, trong khi các gói dữ liệu cuối cùng vẫn còn đang bay trên mạng hoặc nằm chờ ACK trong `pcb->retransmit_q`. Khi mạng bị trễ hoặc rớt gói, client nhận FIN sớm sẽ kết thúc kết nối trước khi nhận đủ dữ liệu, dẫn đến file bị thiếu từ 1 KB đến 22 KB cuối.
  - *Cách sửa:* Trong `sock_close()`, trước khi chuyển sang `FIN_WAIT_1`, thêm vòng lặp chờ cho tới khi client ACK hết sạch dữ liệu trong `retransmit_q`:
    ```c
    while ((pcb->retransmit_q != 0 || (int32)(pcb->snd_nxt - pcb->snd_una) > 0) &&
           (pcb->state == TCP_ESTABLISHED || pcb->state == TCP_CLOSE_WAIT)) {
      if (killed(myproc()))
        break;
      sleep_prepare(pcb);
      release(&pcb->lock);
      sleep();
      acquire(&pcb->lock);
    }
    ```
- **Lỗi Use-After-Free giữa PCB và Socket:**
  - *Nguyên nhân:* Trước đây khi đóng socket thì gán `s->pcb = 0` và trả `s` về `free_list`, nhưng con trỏ ngược lại `pcb->sock` không được xóa. PCB vẫn tiếp tục sống trên mạng để chờ FIN/ACK. Khi có gói đến, `tcp_input()` gọi `sock_push_eof` vào con trỏ cũ, dễ ghi đè làm hỏng socket của kết nối mới.
  - *Cách sửa:* Đặt `pcb->sock = 0` ngay trước khi đổi trạng thái đóng socket.
- **Dọn dẹp hàng đợi backlog:** Khi socket lắng nghe bị đóng, duyệt và giải phóng toàn bộ socket con còn tồn trong `s->backlog_q` để tránh rò rỉ socket pool.
- **Chuẩn hóa giá trị trả về:**
  - `sock_read()`: nếu buffer rỗng mà kết nối đã nhận FIN/RST hoặc bị đóng thì trả về `0` (EOF) ngay để ứng dụng thoát vòng lặp đọc.
  - `sock_write()`: nếu socket đã đóng hoặc bị đứt kết nối giữa chừng thì trả về `-1` (EPIPE) thay vì trả về 0.

### b. Sửa lỗi kẹt ACK trong `kernel/tcp_input.c`
- Trong trạng thái `TCP_SYN_RCVD`, khi nhận ACK bước 3 của bắt tay thì gọi `tcp_handle_ack(pcb, ack, win)` để dọn gói SYN-ACK ra khỏi `retransmit_q`. Trước đây không gọi hàm này làm gói SYN-ACK bị kẹt lại ở đầu queue; khi mạng rớt gói thì timer chỉ retransmit lại gói cũ đó, khiến curl bị treo timeout 40s (`http=000`).
- Trong `TCP_FIN_WAIT_1` và `TCP_FIN_WAIT_2`, bổ sung `tcp_handle_ack()` để giải phóng nốt các gói dữ liệu cuối cùng và gói FIN khi nhận được ACK từ client.

### c. Viết test tự động (`tests/`)
- Thêm `test_client_abort` trong `tests/state_tests.py`: Client kết nối gửi dở request rồi dùng `SO_LINGER=0` để bắn gói `RST` ngắt kết nối đột ngột. Kiểm tra xem server có nhận biết đứt kết nối, đóng socket và phục vụ tiếp client sau bình thường hay không.
- Viết `tests/run_tests.py`: Script tự động khởi chạy QEMU ở chế độ headless, nạp `httpd`, chạy toàn bộ 6 bài test trạng thái và tắt máy ảo cleanly.

## 3. Kết quả kiểm thử

- **Chạy bộ kiểm thử tự động máy trạng thái (`python3 tests/run_tests.py`):**
  ```text
  test_3way_handshake          ... OK
  test_closed_port_rst         ... OK
  test_half_close              ... OK
  test_fragmented_stream       ... OK
  test_largefile_1mb           ... OK
  test_client_abort            ... OK

  All 6 tests passed.
  ```
- **Kiểm thử tải file 1 MB thật dưới điều kiện rớt gói 10% (`setloss 10`):**
  - Chạy: `curl http://127.0.0.1:20080/largefile.bin -o dl.bin`
  - Dung lượng file tải về: đúng 1,048,576 bytes.
  - So khớp mã băm SHA-256 giữa file tải về và file gốc: trùng khớp 100% (`6a2b04610ee...`), khắc phục triệt để lỗi mất đuôi file.

## 4. Tồn đọng & Kế hoạch Tuần 3
- **Tồn đọng:** Web server hiện tại xử lý đơn tiến trình tuần tự, khi đang truyền file 1 MB thì request khác phải chờ.
- **Kế hoạch Tuần 3:**
  - Nâng cấp bộ đệm vòng `kernel/ringbuf.c` cho an toàn khi đọc/ghi đa luồng.
  - Nghiên cứu mô hình worker pool (`fork()`) cho `user/httpd.c` để phục vụ đồng thời nhiều client.
  - Phối hợp cùng nhóm tích hợp lệnh `netstat` và hoàn thiện báo cáo tuần 3.

## 5. Các tệp đã sửa đổi

| Tệp tin | Thay đổi |

| `kernel/sock.c` | Sửa `sock_close` (chờ ACK `retransmit_q`, gán `pcb->sock = 0`, dọn `backlog_q`), chuẩn hóa mã trả về trong `sock_read` và `sock_write`. |
