## 1. Mục tiêu Tuần 2 (Thành viên 3)

Dựa theo kế hoạch kỹ thuật tại `plans/weeks/week_2.md` và lộ trình cá nhân tại `plans/members/member_3_tv3.md`:
1. **Xử lý triệt để tín hiệu ngắt kết nối trong tầng Socket (`kernel/sock.c`):**
   - Khi client chủ động gửi cờ `FIN` hoặc gửi cờ `RST`, hàm `sock_read()` phải trả về giá trị `0` (EOF) để báo hiệu cho ứng dụng user-space dừng đọc dữ liệu.
   - Hàm `sock_write()` nếu phát hiện socket đã chuyển sang trạng thái `TCP_CLOSED` hoặc đứt kết nối trong quá trình truyền tải phải trả về mã lỗi `-1` (`EPIPE` / Connection Broken) thay vì treo vô hạn hoặc trả về 0 gây hiểu nhầm.
2. **Cơ chế đóng Socket sạch sẽ (`sock_close`):**
   - Hủy liên kết hai chiều giữa Socket và PCB: Đặt `pcb->sock = 0` ngay khi đóng socket để loại bỏ hoàn toàn nguy cơ Use-After-Free khi PCB tiếp tục tồn tại ở các trạng thái đóng (`FIN_WAIT_1`, `LAST_ACK`, `TIME_WAIT`).
   - Dọn dẹp hàng đợi backlog (`s->backlog_q`) của socket lắng nghe, tránh rò rỉ socket struct.
   - Đánh thức mọi luồng đang sleep chờ trên ring buffer và tái khởi tạo trạng thái buffer trước khi hoàn trả socket về `sock_table.free_list`.
3. **Mở rộng bộ kịch bản kiểm thử tự động FSM (`tests/state_tests.py`):**
   - Viết kịch bản kiểm thử ca client đột ngột ngắt kết nối (Client Abort via RST) và đối chứng việc giải phóng tài nguyên socket giúp server tiếp tục phục vụ client tiếp theo mà không bị deadlock hay rò rỉ bộ nhớ.
   - Chạy kiểm thử tự động đầu-cuối qua `tests/run_tests.py` đạt 100% tỷ lệ pass.

## 2. Hiện trạng đầu tuần & Phân tích rủi ro

Qua kiểm tra mã nguồn tầng Socket ở `kernel/sock.c` sau khi tích hợp code từ Tuần 1 và các commit đầu Tuần 2:
1. **Lỗ hổng Use-After-Free giữa PCB và Socket (`sock_close`):**
   - Trong `sock_close()`, khi tham chiếu `s->ref_cnt <= 0`, kernel gán `s->pcb = 0` và đưa `s` vào `sock_table.free_list`. Tuy nhiên, con trỏ ngược lại là `pcb->sock` **không hề được xóa** (`pcb->sock` vẫn trỏ vào địa chỉ của `s`).
   - Nếu kết nối ở trạng thái chủ động đóng (`FIN_WAIT_1`), PCB vẫn sống trên mạng để chờ ACK/FIN từ đối tác. Khi đối tác gửi gói đến, `tcp_input()` gọi `sock_push_eof((struct socket *)pcb->sock)`. Lúc này `s` có thể đã được cấp phát cho một kết nối mới khác, dẫn đến việc ghi đè cờ `eof` làm hỏng kết nối mới.
2. **Rò rỉ kết nối con trong hàng đợi Backlog:**
   - Nếu một tiến trình đóng socket đang lắng nghe (`TCP_LISTEN`), các kết nối con đã hoàn tất bắt tay 3 bước nhưng chưa được `accept()` vẫn nằm treo trong `s->backlog_q` và không bao giờ được giải phóng.
3. **Thiếu phản hồi lỗi `EPIPE` khi ghi vào kết nối hỏng (`sock_write`):**
   - Khi client ngắt kết nối hoặc gửi `RST`, `pcb->state` chuyển sang `TCP_CLOSED`. Nếu `sock_write()` đang sleep chờ giải phóng cửa sổ trượt (in-flight window), nó thức dậy và thoát vòng lặp, nhưng lại trả về `total_written = 0` thay vì `-1`. Điều này vi phạm tiêu chuẩn POSIX (`write` trên socket đã đóng phải trả về `-1`).
4. **Trường hợp treo hoặc đọc sai khi `sock_read` gặp buffer rỗng:**
   - Nếu kết nối đã bị đóng hoặc reset trước khi gọi `sock_read()`, hàm cần nhận diện ngay để trả về `0` (EOF) mà không đi vào chu kỳ sleep không cần thiết.

## 3. Chi Tiết Triển Khai Kỹ Thuật

### 3.1. Hoàn thiện hàm đóng Socket an toàn (`sock_close` trong `kernel/sock.c`)

Cải tạo toàn diện quy trình dọn dẹp tài nguyên socket:
* **Thu hồi hàng đợi Backlog:**
  ```c
  struct socket *q = s->backlog_q;
  s->backlog_q = 0;
  s->backlog_cnt = 0;
  release(&s->lock);

  while (q) {
    struct socket *next_q = q->next;
    q->next = 0;
    sock_close(q);
    q = next_q;
  }
  ```
* **Hủy liên kết hai chiều với PCB:**
  ```c
  if (pcb) {
    acquire(&pcb->lock);
    // huy con tro sock nguoc lai de tranh use-after-free khi pcb con song
    pcb->sock = 0;
    if (pcb->state == TCP_ESTABLISHED) {
      pcb->state = TCP_FIN_WAIT_1;
      release(&pcb->lock);
      tcp_output(pcb, 0, TCP_FLAG_FIN | TCP_FLAG_ACK);
    } else if (pcb->state == TCP_CLOSE_WAIT) {
      pcb->state = TCP_LAST_ACK;
      release(&pcb->lock);
      tcp_output(pcb, 0, TCP_FLAG_FIN | TCP_FLAG_ACK);
    } else {
      release(&pcb->lock);
      tcp_pcb_free(pcb);
    }
  }
  ```
* **Đánh thức sleeper và tái thiết lập ring buffer:**
  ```c
  // danh thuc bat ky tien trinh nao dang cho tren rx/tx buffer
  acquire(&s->rx_buf.lock);
  s->rx_buf.eof = 1;
  wakeup(&s->rx_buf);
  release(&s->rx_buf.lock);

  acquire(&s->tx_buf.lock);
  wakeup(&s->tx_buf);
  release(&s->tx_buf.lock);

  wakeup(s);

  // lam sach trang thai ring buffer truoc khi tra ve free_list
  ringbuf_init(&s->rx_buf);
  ringbuf_init(&s->tx_buf);
  ```

### 3.2. Chuẩn hóa mã trả về EOF (0) trong `sock_read` (`kernel/sock.c`)

* Kiểm tra trạng thái cạn dữ liệu khi kết nối đã đóng hoặc reset:
  ```c
  // neu buffer da can va remote da gui fin hoac connection reset thi bao eof (0)
  if (ringbuf_avail(&s->rx_buf) == 0) {
    if (s->rx_buf.eof || !s->pcb || s->pcb->state == TCP_CLOSED)
      return 0;
  }
  ```
* Khi `ringbuf_read()` trả về `<= 0` (do cờ `eof` được bật khi nhận `FIN` hoặc `RST`), `sock_read()` lập tức trả về `0` cho ứng dụng user-space để thoát vòng lặp đọc mà không bị treo.

### 3.3. Xử lý lỗi `EPIPE` (-1) trong `sock_write` (`kernel/sock.c`)

* Kiểm tra ngay từ đầu trạng thái socket:
  ```c
  // socket da o trang thai dong thi bao loi epipe (-1)
  if (pcb->state == TCP_CLOSED ||
      (pcb->state != TCP_ESTABLISHED && pcb->state != TCP_CLOSE_WAIT))
    return -1;
  ```
* Khi tiến trình đang đợi giải phóng cửa sổ (`in_flight`) mà đối tác ngắt kết nối (nhận RST hoặc timeout), `wakeup(pcb)` được gọi:
  ```c
  // neu ket noi bi ngat hoac chuyen sang tcp_closed trong luc cho
  if (pcb->state != TCP_ESTABLISHED && pcb->state != TCP_CLOSE_WAIT) {
    release(&pcb->lock);
    if (total_written == 0)
      return -1; // epipe: socket hong ngay truoc khi gui duoc byte nao
    break;
  }
  ```
* Xử lý trường hợp cấp phát mbuf hoặc lỗi truyền gói khi chưa gửi được byte nào thì luôn trả về `-1`.

### 3.4. Mở rộng bộ kiểm thử tự động `tests/state_tests.py`

Bổ sung **Test 6: Client Abrupt Reset & Clean Socket Reclaim (`test_client_abort_and_socket_reclaim`)**:
* Sử dụng tùy chọn `SO_LINGER` với thời gian chờ bằng 0 (`struct.pack('ii', 1, 0)`) để ép hệ điều hành Host gửi gói `TCP RST` thay vì `FIN` khi đóng kết nối client.
* Kịch bản:
  1. Client 1 kết nối đến Web Server, gửi dữ liệu dở dang (`GET /`), sau đó ép gửi `RST` đóng socket đột ngột.
  2. Xác minh Web Server trên xv6 không bị crash, `sock_read`/`sock_write` phát hiện đứt kết nối và gọi `close()`.
  3. Client 2 lập tức kết nối tới server, gửi yêu cầu chuẩn `GET /README HTTP/1.0`.
  4. Xác minh server phản hồi `HTTP/1.0 200 OK` với đầy đủ dữ liệu (6,840 bytes), chứng minh socket cũ đã được thu hồi sạch sẽ và socket pool sẵn sàng phục vụ tiếp.
